# System Architecture Notes

## Day 22 – Multi-Agent System Design

### Project: AI Research Assistant

### 1. Introduction

The AI Research Assistant is a multi-agent system designed to automate research activities through collaboration between specialized AI agents.

Instead of using a single AI agent for the entire task, the system distributes responsibilities among five agents: Research, Analyzer, Critic, Writer and Coordinator.

### 2. System Architecture

The system follows a coordinator-based architecture in which the Coordinator Agent manages task execution and communication.

The architecture consists of the following components:

- User Interface
- Coordinator Agent
- Research Agent
- Analyzer Agent
- Critic Agent
- Writer Agent
- Shared State
- Final Output Generator

### 3. Agent Roles

**Research Agent**

- Collects information related to the user's query.
- Searches available research sources.
- Organizes findings for further processing.

**Analyzer Agent**

- Processes collected research information.
- Extracts important insights.
- Identifies patterns and relevant details.

**Critic Agent**

- Reviews research findings and analysis.
- Identifies errors, missing information and unsupported claims.
- Provides correction feedback.

**Writer Agent**

- Converts validated information into structured content.
- Generates the final research report.

**Coordinator Agent**

- Manages the overall workflow.
- Assigns tasks to agents.
- Maintains shared state.
- Controls execution and final delivery.

### 4. Communication Architecture

Agents communicate by exchanging structured messages containing task details, results and feedback.

The communication process follows these steps:

1. Coordinator sends the research request to the Research Agent.
2. Research Agent shares findings with the Analyzer.
3. Analyzer sends analysis results to the Critic.
4. Critic provides validation feedback.
5. If corrections are needed, the Coordinator routes the task back to the relevant agent.
6. Once validated, the Writer generates the final report.
7. Coordinator delivers the final result.

### 5. Shared State Management

Shared state acts as a common information store for all agents.

It maintains the following information:

| State Variable    | Description                             |
| ----------------- | --------------------------------------- |
| research_query    | Original user question                  |
| research_findings | Information collected by Research Agent |
| analysis_results  | Insights generated by Analyzer          |
| critic_feedback   | Review comments from Critic             |
| validation_status | Current validation result               |
| final_report      | Completed research document             |
| workflow_status   | Current execution stage                 |

Shared state helps prevent unnecessary repeated work and allows agents to access relevant intermediate results.

### 6. Workflow Planning

The workflow follows a sequential execution model with a conditional feedback loop.

**Execution Order:**

1. Receive user query.
2. Initialize shared state.
3. Assign research task.
4. Collect and analyze information.
5. Validate the results.
6. Repeat corrections if required.
7. Generate the final report.
8. Deliver the output.

### 7. Error Handling

The system should handle common workflow errors:

- Research Agent failure: Coordinator retries or reports unavailable information.
- Analyzer failure: Reprocess the available findings.
- Critic rejection: Send feedback for correction.
- Writer failure: Retry report generation.
- Communication failure: Preserve the last successful shared state and retry message delivery.

### 8. Quality Control

The Critic Agent acts as the quality-control component.

It checks:

- Information accuracy.
- Relevance to the research query.
- Missing details.
- Unsupported statements.
- Report completeness.

A maximum of three review attempts can be configured to prevent endless feedback loops. If the report still fails validation, the Coordinator should flag the unresolved issues instead of marking it as approved.

### 9. Benefits of the Architecture

- Modular and reusable agent design.
- Clear separation of responsibilities.
- Better coordination and communication.
- Shared information management.
- Improved quality through validation.
- Easier maintenance and future expansion.

### 10. Conclusion

The proposed architecture provides a structured approach to building collaborative AI systems. By combining specialized agents, shared state management and controlled communication, the AI Research Assistant can perform complex research tasks in an organized and reliable manner.
